# Механика времени

Ключевое разделение: **Lesson — правило**, а **вхождение — событие**.
Все часы, конфликты и блокировки считаются по вхождениям.

## Недели и даты

- номера недель — **с 1**, всего `AcademicCalendar.weeks`;
- дата дня `weekday` недели `k`: `startDate + (k − 1) × 7 + weekday`;
- weekday ∈ {Monday…Saturday} (Sunday не существует).

## Шаблон недели и валидность дня

Шаблон недели для недели `k`:
`overrides[weekIndex = k].patternId` (если есть) иначе `defaultPatternId`.

День (неделя `k`, weekday `w`) **валиден**, только если:
1. `days[w].templateId` в шаблоне недели ≠ `null` (не выходной по
   шаблону);
2. дата НЕ входит в `AcademicCalendar.holidays`.

## Слот и вхождение

- слот задаётся `DayPatternItem` с `index = Lesson.slotIndex`
  (слоты нумеруются с 1);
- **вхождение** урока (неделя `k`) существует, если:
  - день валиден (пункт выше),
  - в шаблоне дня есть слот с таким `slotIndex`,
  - неделя удовлетворяет `parity` урока (см. ниже).
- время вхождения: `DayPatternItem.start – DayPatternItem.end`
  соответствующей даты.
- Если вхождение не существует (короткий шаблон, выходной, праздник) —
  это `SlotUnavailable` (warning): часы не начисляются,
  конфликтов нет, сетка на такую дату заблокирована для перетаскивания.

## Парность

| Parity | Недели |
|---|---|
| `Above` («над чертой») | нечётные: 1, 3, 5, … |
| `Below` («под чертой») | чётные: 2, 4, 6, … |
| `Both` | все |

Одна неделя может содержать урок с `Above` и урок с `Below`
в одном слоте — это разные вхождения в разные недели,
конфликта «одновременно» нет.

## «Прошёл» и блокировки

- вхождение «прошло» (фактически проведено), когда его **окончание**
  (datetime по `end` слота) стало меньше текущего времени;
- прошедшие вхождения **нельзя** удалить или изменить:
  это история и источник `hoursConducted`;
- граница «прошлого» вычисляется **для каждого урока отдельно**
  по datetime его слота, а не по календарной неделе целиком
  (пятничный урок недели, где понедельник–среда уже прошли,
  ещё не «прошёл»).

## Дробление weekRange

Если Lesson частично в прошлом:
- **старый** Lesson фиксируется: `weekRange` обрезается до последней
  недели, в которой слот этого урока прошёл (`to` включительно);
  праздник или короткий шаблон границу не двигают — «прошло» только
  существующее вхождение;
- **новый** Lesson создаётся с остатком диапазона
  (от следующей недели до исходного `to`), только если в остатке есть
  вхождения: правило без вхождений не создаётся;
- дробление идемпотентно, выполняется сервером при любом
  чтении/записи уроков проекта и персистится в БД;
- прошедшие вхождения в обоих фрагментах идентичны — история
  не меняется, меняется только граница диапазона.

Прошедшие недели вообще не назначаются: при создании и правке
`weekRange` обрезается по будущим неделям (дефолт нового занятия —
с первой непрошедшей недели); ручной выбор прошедших недель в форме
показывает предупреждение, а сохранение режет их.

## Расчёт часов

- часы считаются в **академических часах**: 1 акад. час = 45 мин;
- длительность слота → часы, округление **вверх** до целого:
  обычная пара (90 мин) = 2; сокращённая (45 мин) = 1; 50 мин = 2; 120 мин = 3;
- `hoursScheduled` урока = сумма часов **существующих** вхождений
  по всему `weekRange`;
- `hoursConducted` урока = сумма часов **прошедших** вхождений;
- `hoursScheduled`/`hoursConducted` нагрузки = суммы по её Lesson;
- исчезновение вхождения (добавление праздника, изменение шаблона)
  автоматически возвращает часы в остаток нагрузки — пересчёт
  на лету, данных не пересобирать.

## Пример

Календарь: 16 недель, 1-я неделя — `startDate`. Шаблон «Стандартный»
— 6 слотов; override на 13-ю неделю — шаблон «Сокращённый» (4 слота).
Урок: Lecture, группа A, понедельник, slotIndex = 5, parity Both,
weekRange [1..16].

- вхождений: 15 (в 13-й неделе 5-го слота нет → `SlotUnavailable`
  warning, сетка этой недели/слота заблокирована);
- `hoursScheduled` = 15 × 2 = 30 ч (при слоте 09:00–10:30);
- если сегодня — 4-я неделя: `hoursConducted` = 4 × 2 = 8 ч,
  дробление: старый Lesson [1..4] (зафиксирован), новый [5..16].
