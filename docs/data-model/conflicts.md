# Конфликты

Конфликты вычисляются **на лету** и не хранятся в БД.
Возвращаются через `GET /projects/:projectId/conflicts`
(предварительно; уточнить при проектировании API).

## Типы и severity

```typescript
enum ConflictType {
  TeacherDoubleBooked, // преподаватель одновременно на двух парах; error
  RoomDoubleBooked,    // аудитория занята одновременно двумя занятиями; error
  GroupDoubleBooked,   // группа (или подмножество потока) уже занята в это время; error
  RoomCapacity,        // комната слишком мала для размера группы/потока; warning
  SlotUnavailable,     // в шаблоне дня этой недели нет слота с данным slotIndex; warning
}

interface Conflict {
  type: ConflictType;
  lessonIds: ID[];
  message: string;
  severity: 'error' | 'warning';
}
```

- **error — блокирует сохранение урока** (неконсистентное расписание
  нельзя показывать студентам): TeacherDoubleBooked, RoomDoubleBooked,
  GroupDoubleBooked;
- **warning — не блокирует**: RoomCapacity, SlotUnavailable.

## Правила детекции

Все проверки выполняются на уровне **вхождений** (расширенных до
конкретных дат/времен; см. `time-mechanics.md`), а не на уровне правил:

| Тип | Условие |
|---|---|
| TeacherDoubleBooked | два вхождения с одним `teacherId` пересекаются по времени (одинаковые дата и интервал `start–end` — слоты из шаблона дня недели) |
| RoomDoubleBooked | два вхождения с одним `roomId` совпадают по дате и слоту |
| GroupDoubleBooked | вхождения имеют пересечение `groupIds` и совпадают по дате/слоту (учитываются подмножества потоков) |
| RoomCapacity | сумма `StudentGroup.size` по `groupIds` урока > `Room.capacity` |
| SlotUnavailable | в шаблоне дня для недели(й) из `weekRange` нет слота с этим `slotIndex` (в т.ч. если день — выходной или праздник) |

Парадность исключает ложные срабатывания: вхождения уроков с
разной парностью выпадают на разные недели и конфликтом «одновременно»
не являются.

Прошедшие вхождения в конфликты не попадают: они зафиксированы
дроблением и правке недоступны (`time-mechanics.md`), поэтому чинить
такой конфликт негде. Конфликт живёт, пока у него есть хотя бы одно
непрошедшее вхождение.

## Влияние на UI

- при сохранении/перемещении урока: error-конфликты блокируют операцию;
- в сетке: помечаются только уроки с error-конфликтами (красная рамка
  и значок); warnings (в т.ч. RoomCapacity при слиянии в поток —
  неблокирующее предупреждение) карточку не помечают — они видны
  в доке конфликтов и в предпросмотре диалога;
- `SlotUnavailable` не переносит и не отменяет урок: вхождения
  в этих неделях просто не существуют, часы не начисляются.
